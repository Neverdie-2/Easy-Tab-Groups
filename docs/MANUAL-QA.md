# Manual QA — Load Unpacked & verify by hand

A hands-on checklist to load **Easy Tab Groups** into Brave (or any Chromium
browser) and confirm every feature works, plus the privacy/zero-network
guarantees. Automated gates (`typecheck`, `lint`, `test`, `build`, the
no-network guard) cover the logic; this document covers the parts that need a
real browser.

Tick each box. If any step fails, the extension is **not** shippable.

---

## 0. Build the loadable extension

```bash
npm install
npm run build        # emits the loadable MV3 extension to ./dist
```

- [ ] `npm run build` completes with no errors.
- [ ] `dist/` now contains: `manifest.json`, `service-worker.js`,
      `dashboard.html`, `assets/` (a `dashboard-*.js`, a `dashboard-*.css`,
      and a shared `storage-*.js`), and `icons/` (16/32/48/128 px).

> `dist/` is git-ignored and regenerated by every build. **Load the `dist/`
> folder, not the repo root** — `manifest.json` lives at the root of `dist/`.

## 1. Load unpacked

1. Open `brave://extensions` (or `chrome://extensions`).
2. Toggle **Developer mode** on (top-right).
3. Click **Load unpacked** and select the **`dist/`** folder.

- [ ] The extension appears as **Easy Tab Groups** with no load errors.
- [ ] Click **Details → Permissions**. It requests **only**: read your browsing
      _tabs_, and _tab groups_. There is **no** "Read and change data on
      websites" / host access. (Storage/unlimitedStorage/favicon are not shown
      as scary host warnings.)
- [ ] Click **Service worker** (under "Inspect views"). The console shows **no
      errors** and no failed network requests.

## 2. First run & opening the dashboard

1. Click the **Easy Tab Groups** toolbar icon (pin it if hidden).

- [ ] A **full-page dashboard** opens in its own tab (not a small popup).
- [ ] A **Welcome** first-run intro appears explaining Capture → File → Close →
      Reopen and the zero-network promise. Click **Get started** to dismiss.
- [ ] Reopening the dashboard (click the icon again) **focuses the existing
      dashboard tab** instead of opening a second one.
- [ ] The header shows the **🔒 Local-only** badge and a `0 saved · 1 folder`
      style stat line. The left pane lists your currently open tabs grouped by
      window; the right pane shows an **Inbox** folder and an empty-state hint.

## 3. Capture (import open tabs)

_Setup: open ~10 tabs across a couple of domains first (e.g. several
`opensea.io` pages and some others), in one or two windows._

1. In the left pane, click **Refresh** — the open-tab count updates.
2. Click **Import open tabs**.

- [ ] The status bar reports `Imported N tab(s) into the Inbox.`
- [ ] The right-pane **Inbox** folder count increases by N.
- [ ] The dashboard's **own tab is NOT captured** (it never appears in the left
      pane or gets saved/closed).

## 4. Filter, select-all-matching, batch-move into a nested folder

1. In the left pane's filter box, type a domain (e.g. `opensea`). The list
      narrows; the datalist suggests domains.
2. Click **Select all matching (N)**.

- [ ] Only the matching tabs are selected; the `N selected` counter matches.

3. Ensure **Close after filing** is checked. Click **Move to folder…**.
4. In the picker, type a name in **New top-level folder name…** (e.g.
      `Base chain`) and click **Create & move** — _or_ pick an existing folder.

- [ ] The status bar reports `Filed N tab(s) and closed them.`
- [ ] Those tabs **close in the browser** (RAM freed) and the open-tab count
      drops.
- [ ] The new folder in the right pane holds exactly those N tabs.

5. Build depth: on `Base chain` click **＋**, add `Blupets`; expand it, click
      **＋** on `Blupets`, add `Gold trait`. Drag a couple of saved tabs (or
      file more) into `Gold trait`.

- [ ] Unlimited nesting works: `Base chain › Blupets › Gold trait › tabs`.

## 5. Reopen a folder as a native tab group

1. On `Gold trait` click **Open**.

- [ ] The saved tabs reopen **in the browser** and are wrapped in a **native
      tab group** titled **Gold trait** with a colour.
- [ ] The tabs appear in the **saved order**.

2. Tick **Include subfolders** (top of the right pane). Click **Open** on
      `Base chain`.

- [ ] A native group titled **Base chain** opens containing that folder's tabs
      **and** all descendant folders' tabs (depth-first).
- [ ] Reopening the same folder twice keeps the **same group colour** (stable).
- [ ] Clicking **Open** on an **empty** folder opens nothing and creates no
      empty group.
- [ ] The **Open** button on an individual saved tab row opens just that one
      tab (foreground).

## 6. Rename / reorder / drag / delete

- [ ] Double-click a folder name (or click ✎) → inline edit → Enter renames it.
- [ ] `↑` / `↓` reorder a folder among its siblings; order persists after a
      dashboard refresh (reload the page).
- [ ] Drag a folder onto another folder row → it moves **into** that folder.
- [ ] Drag a folder onto the **"Drop a folder here to move it to the top
      level"** zone → it becomes top-level.
- [ ] Drag a saved-tab row onto a folder → the tab moves into that folder.
- [ ] The **Inbox** folder cannot be renamed, deleted, reordered or dragged
      (no ✎/🗑/↑/↓, drag does nothing).
- [ ] 🗑 on a non-empty folder asks for confirmation, then deletes the folder,
      its subfolders and their tabs.

## 7. Search

1. In the right-pane search box, type a word from a saved title/url/domain.

- [ ] Matching saved tabs are listed with their **folder path** as a subtitle.
- [ ] Multiple space-separated words require **all** to match (AND).
- [ ] Clearing the search restores the folder tree.

## 8. Dedupe finder

_Setup: import the same tab twice (or file the same URL into two folders)._

1. Click **Find duplicates** in the toolbar (it shows a count when > 0).

- [ ] Duplicate groups are listed; the earliest-saved copy is marked **keep**
      (its checkbox disabled) and the rest are pre-checked **remove**.
- [ ] Toggling **Ignore #hash / ?query / trailing /** re-groups accordingly.
- [ ] **Remove N duplicates** deletes only the checked copies; the kept copy
      remains and the toolbar duplicate count drops.

## 9. Export / Import round-trip (never locked in)

1. Toolbar → **Export / Import** → **Export JSON**.

- [ ] A `easy-tab-groups-YYYY-MM-DD.json` file downloads.

2. Click **Export HTML bookmarks**.

- [ ] A `.html` file downloads and opens in a browser as a normal nested
      bookmark list (folders → headings, tabs → links).

3. Re-open the dialog, choose the JSON file under **Import**, pick **Replace
      everything**, click **Import**.

- [ ] Status reports the folder/tab counts and the vault matches what you
      exported (structure and links intact). The Inbox still exists.
- [ ] Try importing a deliberately broken/non-JSON file → a clear error is
      shown and the vault is **unchanged**.

## 10. Persistence across restart

1. Fully quit and reopen the browser, then open the dashboard again.

- [ ] All folders and saved tabs are still there (IndexedDB survived).
- [ ] The first-run intro does **not** reappear.

## 11. Zero-network / privacy verification (the headline promise)

1. In `brave://extensions`, open the **Service worker** inspector → **Network**
      tab. Exercise capture and reopen.

- [ ] **No network requests** are made by the service worker.

2. On the dashboard tab, open DevTools → **Network** tab, then use every
      feature (import, file, reopen, search, dedupe, export).

- [ ] The only non-`data:`/`blob:` requests are to `chrome-extension://<id>/…`
      (the dashboard's own JS/CSS and `_favicon/?pageUrl=…` icons). **Zero**
      requests go to any `http(s)://` host on the internet.

3. Favicons.

- [ ] Saved/open tab rows show real favicons from the browser's **local** cache
      (`_favicon/`); tabs with no cached icon show a coloured **letter chip**,
      never a broken image and never a remote fetch.

4. XSS safety.

- [ ] Save a tab whose page title contains HTML, e.g.
      `<img src=x onerror=alert(1)>`. It renders as **literal text** in the row
      and in the exported HTML file — no alert, no injected element.

---

## Sign-off

- [ ] All sections above pass on Brave.
- [ ] `npm run typecheck && npm run lint && npm run test && npm run build && npm run guard:network` are all green.

If every box is ticked, the build is good to ship.
